# 主动式超级智能体：Yoyo 的产品与技术方案

审阅：2026-11-03。这是给 owner 的构建方案，不是论文转写。文献卡片在 [research/](research/README.md)。扫读件已补进 [research/report.html](research/report.html)。

基线有两份，不再加第三套运行时：

- 领域与注意力纪律：[dsh-superagent-prototype](../../dsh-superagent-prototype/docs/000-philosophy.md) 的哲学，以及 [001 领域模型](../../dsh-superagent-prototype/docs/001-domain.md)。来源产出触发，评估决定接单、忽略或未完成，工单才授权执行。
- 执行器是一次 harness 会话。原型里它是 DeepSeek Harness 的 Session；Yoyo 用进程内的 Go 循环站在同一个位置（`internal/runtime`、`internal/dsh`、`internal/superagent`）。路由只拿 `task_route`、`task_status`、`task_note`、`task_stop`、`memory_read`。工人是另一段会话，一次一张工单。

主动式要补的是开口，不是再做一个会聊天的壳。

## 1. 现在缺的是判断，不是素材

Yoyo 已经有主动式的零件：

| 零件 | 落点 | 已经做到 |
| --- | --- | --- |
| 准入模式 off / observe / auto | `internal/superagent/policy.go`、`engine.go` | 推断候选在非 auto 下只记 `observed`，不开工单 |
| 日程、GitHub、飞书来源 | `internal/superagent` | 触发进评估；人的明确请求才能接单 |
| 晨间 / 晚间信 | `frontend/src/features/superagent/desk-feed.ts`、`work-model.ts` | 到点生成卡片，按钮只填进输入框 |
| 本机清点 | `internal/poi/census.go` | 目录名、清单名、大小、修改时间 |
| 画像与记忆 | `internal/memory/memory.go` | 事实直接留下；画像与模型读到的 `ProfilePin` 是同一批事实 |

效果仍然弱，是因为**推送不经过评估**。前端时钟到了就写一封信。空桌面、重复的作息、一个安装包，都会占掉主会话的一条消息。原型的纪律是：只有人必须行动，或一份结果用得上，才开口。现在的信违反了这条。

2026 年 Ke Yang 等人的综述把主动式定义成：没有针对这一次行动的明确指令时，自己发起朝向目标的行动。主动性和授权是两件事。技术机制收成六种能力（6A）：掌握情况、预判、形成议程、判断介入、落实行动、从反馈里调整。其中真正区分主动式的是预判和判断介入。评估要同时看结果、机制和人的负担。原文没有 arXiv 号，卡片见 [research/corpus/yang-2026-proactive-6a.md](research/corpus/yang-2026-proactive-6a.md)。公众号转述：[2Ge6Pp2oCAk8fZx7NUE3dg](https://mp.weixin.qq.com/s/2Ge6Pp2oCAk8fZx7NUE3dg)。

用这六项看现在的代码：

| 能力 | 已经有的 | 弱点 |
| --- | --- | --- |
| 掌握情况 | 清点名字与时间、画像、排队里的日历、来源错误 | 是一份快照，没有「不确定 / 未核对」。日历没接上时，信不会写自己看不见日程 |
| 预判 | 工程线标成在动、停在空文件、安静 | 只描述当下。没有「保持沉默会怎样、开口要花掉多少注意力」 |
| 议程 | 工单、规则、定时任务 | 信存在浏览器本地，引擎看不见。定时任务另开一段会话，不经过评估 |
| 判断介入 | 人的消息和写成的规则走 `policy.Gate`；observe 只记录 | 晨间信和兴趣库变化不走这道门。到点就 `DeskPush` |
| 行动 | 按钮只填进输入框；对外发送仍要批准 | 行动只有「推一条」和「派工人」两档。没有先准备、等人看的只读档 |
| 适应 | 观察记录能在信里出现；设置里可以忘掉一条记忆 | 信没有接受、忽略、事实错了、此刻别提醒。忽略之后第二天照样推 |

所以效果差，集中在两处。判断介入被时钟绕开：`desk-feed.ts` 的 `ensureBrief` 在档期到了就推，`refreshPoi` 在名字有增减时也推。议程有两条互不相认的路：主会话的工单，以及 `runIsolatedJob` 直接 `NewSession` 去跑定时提示。

拉开看，市面上的主动式产品分成两种，Yoyo 只该走第二种的纪律、第一种的形态：

- **总是在场的云电脑**（Muse、Cue、Dots、Grok Bot）能在人离开后继续干活。Yoyo 不复制他们的虚拟机、电话、钱包。
- **先决定要不要开口，再决定说什么**（2026 年的 ProAgentBench、Liu 等人的触发器、Tang 等人的服务决策综述）。Yoyo 的门已经是这个形状，信还没接上去。

## 2. 文献怎么用

谱系（2024–2025，不当成前沿）：

- Lu 等人，[Proactive Agent](https://arxiv.org/abs/2410.12361)，ICLR 2025。从活动里预测一件事，由人标接受或拒绝，再训一个奖励模型。可取的是「接受 / 拒绝」这张标签。不训模型，也不采用他们的 6790 条事件集。
- Yang 等人，[ContextAgent](https://arxiv.org/abs/2505.14668)，NeurIPS 2025。先判断有没有必要帮忙，再调工具。可取的是这两步。不接眼镜、麦克风和常开摄像头。
- Horvitz，[Principles of Mixed-Initiative User Interfaces](https://doi.org/10.1145/302979.303030)，CHI 1999。开口要考虑打断的代价，并允许人把主动权拿回来。这是注意力纪律的学术前身，原型已经把它写成了产品句子。

2026 年，三篇直接约束实现：

- Tang 等人，[ProAgentBench](https://arxiv.org/abs/2602.04482)（2026-02-04）。先预测时机，再生成协助内容。时机错了，要么打断人，要么错过该帮的那一次。
- Liu 等人，[Do Proactive Agents Need an LLM to Decide When to Act?](https://arxiv.org/abs/2605.30152)（2026-05）。常开路径上不该跑大模型。活动是事件，不是一篇待摘要的文章。触发器要便宜；语言模型只在触发之后写那一句给人看的话。
- Tang 等人，[Proactive Service Agents](https://arxiv.org/html/2609.03727)（2026-09）。一次决策在沉默、询问、协助、行动里选。等待有期权价值。授权不够就没有行动。离线分类分数不能代替部署后的负担。长期记忆不是主动式的定义。

因此 Yoyo 的主动式是：

1. 来源把世界收成触发。时钟、日历、本机清点的差异、GitHub、飞书，都是来源。评估不自己制造延迟触发。这一点原型已经拒绝过。
2. 门是确定性的。它回答开不开口。大模型不站在每 30 秒的兴趣库刷新上。
3. 开口之后才允许研判或写一句话。这句话必须能指回一条证据。
4. 行动（改文件、发消息、花钱）仍然要授权。无人值守时只读。

Today 的桌面形态（本会话里的界面，不是论文）已经说明个人侧的版式：第一封信来自这台机器上能核对的名字；记忆是画像加夹，不让人点「留下 / 忘掉」；周末没有日程时，继续或停下不替人按按钮。Yoyo 的信和记忆页已经按这个版式接上本地证据。下一步是让**推送**服从同一条证据纪律。

## 4. 产品方案

一个主会话。工人是工单，不是名册上的另一个人。主动权有四种强度，全部能映射回已有概念：

| 人看到的 | 领域里是什么 | 默认 |
| --- | --- | --- |
| 人刚说的请求 | 明确触发，评估可接单 | 接单 |
| 写成规则的推断 | 推断触发。observe 只记录；auto 且规则启用才接单 | observe |
| 一条用得上的短讯 | 触发经过门，去向是记下并投递一句话，**不开工单** | 见下面的价值规则 |
| 什么都不发生 | 触发被忽略，或来源根本不产出 | 常态 |

短讯不是新概念。去向（Disposition）本来就记录一条触发被过滤、评估或扇出。给它一个原因 `note`：投递一句话，不创建工单，不调用工人工具。

### 4.1 拉开和推送

- **拉开** Today：人点开今天，总是能看到当前证据拼出的信。空也要有一封，说明没有信号。这是阅读，不消耗打断。
- **推送**：只有价值规则通过，才往主会话放一条芯片。芯片点开同一封信。

Pulse 被收进定时任务，是因为一条单独的每日流留不住。Yoyo 不再加第二条信息流。

### 4.2 价值规则（确定性，写死）

一天里，推送只在这些变化上开口。同一天同一类只开口一次。

开口：

- 日历上有今天到期或已经过期、且还在两周窗口里的事项
- 有工单卡住、失败，或在等人
- 来源处于错误
- 某条工程线的状态变了（新出现、从在动变成停在空文件、或反过来），且和上次推送时的签名不同
- 这台机器上的第一封欢迎信还没给过

沉默：

- 作息区间和上次相同
- 只是「装了某个应用」或下载目录里多了一个安装包
- 画像正文没有变化
- 周末，且没有上面任何一条开口条件。信可以在拉开时显示「继续还是停下，这次不替你选」，但不推送

连续三次被标成没用的那一类，停止推送，直到人在偏好里打开。这是本地计数，不是奖励模型。

### 4.3 话说完怎么收住

- 推送正文只引用证据：名字、日期、文件名、状态。不写新闻、健康读数、命中率、文件正文。
- 按钮把任务放进输入框，不发送。没有证据支持的选择不放按钮。
- 发信、评论、付款、改外部系统，继续走现有的批准。无人值守的主动研究不拿写工具。这和 Dots 的只读研究、Muse 的 Sentinel、原型里「工人不能擅自 send_as_you」是同一条边界。
- 例行来自人已经接受过的做法：先试跑（observe，看它会接什么），人打开 auto 之后，同一条规则才接单。不从一次成功自动晋升成例行。

### 4.4 记忆的位置

画像是上下文，不是主动式本身。Tang 等人的综述把这一点说清楚了：长期记忆不是主动的定义。`ProfilePin` 让路由读到已经留下的事实。只有 `FileMachine` 发现签名变化时，才成为一条来源事件。清点结果没变，就不刷新推送，也不改「更新于」。

## 5. 技术实现

不新增领域类型。不加向量库，不训触发模型，不把前端做成第二套循环。

```
来源（时钟、日历、清点差异、GitHub、飞书）
        │ 触发，id 稳定，重启不重放
        ▼
确定性的门（off 丢掉；observe 只记录；价值规则决定 note 或 ignore）
        │
        ├─ ignore     不推送
        ├─ note       主会话一条短讯，不开工单
        └─ accept     仅明确请求或已启用规则。派工给 harness 工人
```

和代码的对应：

| 步骤 | 改哪里 | 保持不动 |
| --- | --- | --- |
| 1. 价值规则 | 新的纯函数，放在 `internal/superagent` 旁边或 `internal/poi` 的签名比较里。输入是清点、工单、日历、上次推送签名。输出是开口或沉默 | `session.Acquire` 的 `ErrBusy`；路由工具表 |
| 2. 推送改成去向 | `internal/app/desk_push.go` 在写入前问价值规则。同一 id（`brief:{slot}:{day}`、`line:{name}:{state}`）已在轨迹里则不再写 | 芯片点开仍是现在的信 |
| 3. 来源化 | 晨间、晚间的时间是来源的时钟，由 Go 在到点时产出一条触发。前端 30 秒刷新只负责拉开时的阅读，不再当推送的权威 | 评估不自己 `sleep` 造触发 |
| 4. 反馈 | 信上的「没用」写本地计数。三类之后该类沉默 | 不上传，不训练 |
| 5. 例行试跑 | 已有的定时规则继续是 Policy 里的规则。保存时默认 observe；试跑把「会接什么」记下来给人看 | auto 只能由人打开 |

DeepSeek Harness 的位置：接单之后的执行仍然是一次工人会话，工具、技能、批准在 `internal/runtime`。主动式代码停在触发和去向，不在工人循环里再判一次「要不要主动」。

签名用清点里已经有的字段即可：工程线的名字和状态、到期事项的 id、工单 id 与 stage。不读正文。

### 分期

顺序按六种能力里最缺的两段来，不并行开新感知。

1. **判断介入。** 价值规则加上单测。不通过就不 `DeskPush`。兴趣库的名字增减同样要过这道规则。拉开 Today 的行为保持。
2. **去向。** `note` 与 `ignore` 分开记。观察模式能在任务栏看见「会说但没说」的那条，占用一行，不进对话。
3. **适应。** 信上的四种反馈：用上了、忽略、事实错了、此刻别提醒。忽略和「此刻别提醒」停掉那一类，同一天不换个说法再推。事实错了走现有的忘掉。不把「人接受了」训成更会劝的说法。
4. **议程收成一条路。** 通过门的候选写成一条带理由、期限和优先级的承诺，引擎能读到。定时任务的触发改成来源事件；接单之后才 `NewSession`。`runIsolatedJob` 不再自己决定开工。
5. **预判保持确定性。** 每条候选只比较两句本地后果：沉默会让到期或停滞继续；开口今天已经花过一次。不建世界模型。
6. **掌握情况补上未知。** 连接器没开、日历没读到，信里写「未核对」，不用空列表假装今天没有会。仍只记名字、时间和状态。

做完 1–3 之前，不加新的来源种类，不接健康，不接常开感知。第 4 步之前，不让晨间信派工人。

## 6. 明确不做

- 不训 ProactiveAgent 那种奖励模型，也不在每条文件事件上跑语言模型。
- 不接眼镜、麦克风、健康读数、浏览历史、邮件正文。
- 不给智能体电话号码、钱包或一块云电脑。
- 不做 Bot 名册。多个工人是多张工单。
- 不把记忆做成向量检索。画像保持现在的本地事实。
- 不把晨间信做成第二条必须刷的时间线。

## 7. 怎么知道做好了

用时机错了的两种代价来验收，不引他们的数据集：

- **假阳性**：一个没有到期、没有卡住、没有状态变化的早晨，主会话里不出现新芯片。拉开 Today 仍能读到一封说明「没有新信号」的信。
- **假阴性**：今天有到期事项，或某条线从在动变成停在空文件，当天的第一次推送点名那一件，并且按钮里的任务不编造指标。
- **越权**：同一次推送不创建工单，不调用写工具。observe 下推断规则仍然不开工单。

## 8. 落地记录（2026-11-06）

按第 7 节验收，审阅时三条都不成立。原因在代码里，不在提示词里。

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 假阴性：今天到期、线停在空文件，从来没推过 | 前端每 30 秒调 `PoiRefresh`，`Assess` 每次都把这一类记成「今天说过」，可非到点的那一轮只推检索。记忆页打开时也调它，判断被白白用掉 | `Assess` 只判断，只记新基线。新增 `Deliver`，话真正写进会话之后才记账。会开口的变化在送到前保留原基线。`Told` 记下今天已经说过的那一条，它不再算「会说但没说」 |
| 推送的权威在前端时钟上 | 开口短讯由 `desk-feed.ts` 推 | Go 的送达循环（`internal/app/desk_loop.go`）每分钟刷新、判断、写进主会话、记账。前端只读 `DeskState`。循环由界面第一次读状态时启动，命令行单轮不会往主会话里说话 |
| 适应不存在 | `DeskFeedback` 没有接到桌面 Service、RPC 和 HTTP，界面只在点简报卡时记一次 used，记到的还是不相干的类别 | 接通三处。主会话短讯下有「用上了 · 没用 · 此刻别提醒」，记忆来的短讯另有「事实错了」。偏好页列出被按住的类别，可以打开；公开检索便条有自己的开关 |
| 两份记录互相覆盖 | 每次操作都新开一份 `initiative.Store` | 应用里只打开一份，判断、送达和反馈共用一把锁 |

工单仍由交接写进主会话。工单感知改成只看不说，不再占一次开口。

任务和记忆也按原型面板的原则收了一遍：一行要说清在等谁、需要什么；计数等于它指向的那一列。

- 任务按「需要你 · 进行中 · 停着 · 最近结束」分组，每行有阶段、多久以前和最近一句。在等回答时那一句就是问题，来自结构化字段，不从摘要里猜。任务标签上的数字有人要等时报等人的张数。工单补上接单时刻和报告时刻；编号按数字比，「最近结束」不再是最旧的八张。
- 今天把「需要你」放在最上面：前后两周内的到期日程，以及等人接受的来信。角标就是这一列的条数，空的时候只有一句。
- 记忆页每条写出出处和时间，写错的在夹里忘掉，要点两次。列表上限从 50 提到 500，工单经历不再把本人说过的话挤出画像。
- 记忆的密钥判断不再按子串误伤 `task-`、`token-efficient` 这种写法，同时认出 GitHub、AWS、JWT 和长串乱码这些旧判断漏掉的钥匙。同一句换个大小写或句末标点不再存两份。检索按词打分，中文按相邻两个字，仍然不用向量。
- 任务栏里原来的「定时」写的是 Policy 规则，没有时刻，从来不会按点跑。现在如实叫「规则」，并说明到点就跑的任务在设置里。规则下面列出观察模式记下的「本来会接」，新的在前。试跑的结果第一次在左栏看得见，人看过再决定要不要换成自动。
- `cronDue` 原来把 `0 18 * * 5`（周五）和 `weekday-1800` 都当成每天，`daily` 按 UTC 的 18 点算。现在按本机时刻，认 `daily@HH:MM`、`weekdays@HH:MM`、`weekly@D@HH:MM` 和五段 cron，睡过头六小时内补一次。

还没做，按顺序：

1. **例行走门。** 规则带上时刻，到点产出一条 `routine` 来源的触发；observe 记成「本来会接」，auto 才按那条规则开工。工人要先能只读到期、等人和在做的工单，否则「每日优先事项」这类规则开了工也做不成。时刻的写法对齐 DeepSeek Harness 的 [Schedule](../../deepseek-harness/docs/subsystems/schedule.zh.md)：带类型的时间和显式时区，错过只补最新一次，可以立即试跑，留投递记录。
2. **简报的时刻搬进 Go。** 偏好现在存在浏览器本地，窗口没开就不生成。搬过去之后，拉开今天时没有当天的信，用确定性的审计先顶上，不叫模型。
3. **记忆写入有回执。** 模型写进一条记忆时，会话里留一句「记下了」和撤销。推断出来的先进待确认。
4. **短讯带上证据入口。** 点开一条短讯能看到它来自哪条日程、哪条线或哪条记忆。

## 9. 第二轮落地记录（2026-11-06）

这一轮看了简报、记忆、主会话和工人之间怎么传话，以及工人会话那一页。下面的原因都在代码里。

### 主会话和工人之间

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 人回答工人的问题，工人只收到路由转述的一句 | `orchestrator_continue` 一律按 brief 送，原话不跟着走 | 工人在等回答时改用 attach，原话和 brief 一起送去 |
| 槽满时人对工人说的话丢了 | `DeliverPending` 不管送没送到都标成已投递，`Deliver` 占不到槽就静默返回 | `Deliver` 返回送没送到，只确认送进去的那几句，剩下的返回 `ErrBusy` 等下一次投递 |
| 重启后续上的工人看不到停机期间人说的话 | 续跑分支把待投递的输入直接确认掉 | 跟在「继续。」后面逐句送进去，送到了才确认 |
| 路由给工人记的备注，要等下一句人话才送到 | `Note` 不叫醒工人 | 和别的输入一样走 `OnInput` |
| 同一张工单换了个问题，第二个问题不回主会话 | 回传去重只看工单和状态 | 去重键带上摘要和问题的哈希 |
| 主会话里的系统短讯互相覆盖 | `relayNotice` 同一会话用同一个 id，前端按 id 合并 | id 带上内容和时刻的哈希 |
| 桌面窗口没开时，工人的报告没地方去 | 回传只发给打开着的桌面 | 退回到上次的主会话 |
| 按规则主动接下的工单，工人不知道凭的是哪条规则 | 派工正文里没有这一行 | 写明规则原文，不该做就 dropped。任务页不显示这一行 |
| 输入框里的停会结束整张工单；路由提示词写「打断只停这一轮」，`task_stop` 却结束工单 | 两处都只有 `stop` | 新增 `pause`：只打断这一轮，不再催工人做下去，停成「在等下一条消息」，人再说一句就接着做。顶上的停止才结束工单，要点两次。`task_stop` 用 `mode` 分开：先停一下是 pause，验收通过是 done，不用做了才是 stop |
| 工单停在「待验收」出不来 | 跟着的线程没关之前，工人报做完也不结束工单。主会话 continue 过的工单会跟上主会话那条线程，而它永远不关；能点的只有停止，结果记成已打断 | 只有自己开的线程（比如工人开的拉取请求）才把做完的工单留在等验收，主会话这类上下文线程不挡完成；快照里已经卡住的，启动时收掉。还在等验收的可以「验收通过」（`accept`，记成人确认做完），或「不通过」把哪里不对说给同一个工人，工单回到在做 |
| 编排暂停时对已结束的工单说话，静默失败 | `Say` 不区分这两种情况 | 返回 `paused`；续开失败返回 `mandate` |

### 记忆

- 工人以前看不到人的偏好。现在工人的系统提示里带一份只读的画像（`OperatorPin`，1500 字节以内）：系统和时区、git 名字、人说过的话、偏好、记下的档案。不带主机名、作息和工单经历。和任务说明冲突时以说明为准。
- 人在主会话里说「记住……」「忘掉……」，路由以前只能读。现在有 `memory_write`（只收档案、项目、事实三类，出处记成本人在对话里确认）和 `memory_forget`（机器记下的不删），`memory_read` 带编号。记下之后，回复里用一句话说记下了什么。
- 记忆页每条可以就地改，改过的出处变成本人。机器记下的和像密钥的不能改。
- 公开检索以前会把画像原文发给外部搜索，现在只用项目和事实。

### 简报

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 没什么可说的早上，简报看起来像坏了 | 「没有值得写的」和「模型输出坏了」走同一条失败路 | 素材不值得写时不叫模型，返回 `quiet`。前端写一封安静的信，写明哪些来源没连上、没核对；这一格封存，主会话里不推芯片 |
| 生成失败一次，这一格当天就没了 | 跨过时刻只试一次 | 在重试窗口里每轮再试，直到成功或过期 |
| 系统自己推的短讯被当成人说的话写进简报 | 取最近对话时不分来源 | 跳过桌面、工人、短讯来源，以及简报、短讯、交接、状态这几类 |
| 晚间简报重复早上的话，也不知道今天结束了什么 | 素材里没有早上的信，也没有结束的工单 | 晚间带上早上说过的和最近一天结束的工单。早晚各有自己的要求 |
| 卡片说不清依据 | 模型输出里没有来源 | 每张卡带 `refs`，只认素材里出现过的编号。卡底一行「依据」，工单可以点开，已经结束的标出来 |
| 模型多包一层代码块或多写一句，解析就失败 | 只认整段 JSON | 先找代码块，再找配平的对象。卡片最多六张 |

简报看板按 [DESIGN.md](DESIGN.md) 重写：标题不超过 17px，细线分行，不套卡片，没有渐变，主按钮是墨色。

### 工人会话那一页

- 在等你时，问题放在最上面：等回答写原问题，卡住、失败、没送出去各有一句。等回答时输入框提示改成「回答这个问题」。
- 等验收时列出这张工单改过的文件，来自写成功的工具回报，点开在预览窗口里看；下面是「验收通过」「不通过」和「在文件夹里看」。不通过要写清哪里不对，退回给同一个工人。原来的「看文件」打开的是主会话的检查器，看到的是主会话工作区的改动，不是工人写的东西。
- 顶上有打开目录、打开来源、重试（卡住、失败、没送出去时）和停止。
- 在做却两分钟以上没有动静时，状态行写出来。
- 发给工人失败时，原话放回输入框，并说明没送到。
- 在跑时每 1.5 秒拉一次会话，停着时每 4 秒。

第 8 节的单子还剩：

1. **例行走门**，没动。
2. **简报的时刻搬进 Go**，没动。安静的那一封已经不叫模型。
3. **记忆写入有回执**，做了一半：路由记下之后会说一句，会话里还没有撤销，推断出来的也还没有待确认。
4. **短讯带上证据入口**，做了一半：简报卡有「依据」，主会话短讯还没有。

## 10. 记忆（2026-11-06）

对照主流做法看了五件事：自动挖掘、自动治理、召回、时序和感知源。参照的是 ChatGPT 的记忆和 Sources、Claude 的分类条目、Mem0 写入时和旧记忆比对、Zep 给事实记有效期、Generative Agents 按新近度加权。约束不变：不用向量，常驻循环里不叫模型，记忆留在本机。

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 常驻画像里最新的偏好最先丢 | 画像上限 800 字节。本机名字、时间和工程线写在最前，当事人说的和偏好写在最后，又是旧的在前，超出预算就截掉 | 上限提到 2000 字节。先写当事人说的，再写偏好和模型记下的，本机的放最后；每组新的在前，放不下时先舍掉旧的和本机的。工人画像同样排 |
| 做过的事要模型自己想起来去查 | 经历和项目不进画像，每句话也不带相关的旧记忆 | 每句话按词召回最多三条不在画像里的旧记忆：做过的事、项目、过去的安排。至少对上两个不算常用词的词才带。它跟着这一句进对话，不进系统提示，前缀缓存不动 |
| 常见词和罕见词一样重 | 打分只数对上几个词 | 改成 BM25：少见的词更重，整句对上加分；经历按九十天减半，最低留一半；过去的安排打六折；说过多次的略高 |
| 「明天」「下周三」过几天就没意思了，过去的安排还当成现在 | 原话照存，只有一个记下时间 | 写入时把相对日子换成日期，补在原词后面。说的是会过去的安排时记下到哪天为止，过了就离开画像，召回和读的时候标「已经过去」。光写「周五」「每周五」多半是习惯，不换算；「从明天开始」是状态，不设期限 |
| 改过的记忆丢了最初的日子 | 改写把记下时间换成现在 | 分开最初记下和最近改过。改写、合并、改口都把旧说法放进历史，最多五条 |
| 人改口，新旧两条一起注入 | 只有完全同一句才合并；写入时看不到库里有什么 | 同一句再说只记次数；只差格式的并成一条；相近的旧记忆随回执交回给写的人，比如「代码注释用中文」和「用英文」，由它决定用 `replaces` 换掉还是不管。字面上分不出近义和反义，所以这种不自动合并 |
| 模型记下的盖掉当事人的话 | 合并时不看来源 | 来源分三档：当事人说的、没写来源的旧数据、模型和工人记下的。低的一档不改高的一档的原话 |
| 不知道一条记忆从哪学来 | 只有粗的来源 | 新增 `origin`，写会话或工单。工单结果、会话收拢、普通会话里记下的都带上 |
| 旧数据里有只差标点的重复 | 以前不整理 | 打开时把只差格式的并成一条，经历不并 |
| 别处的话会被当成「你说的」 | 路由写记忆时不核对出处。工人报告、贴进来的网页和邮件都会进主会话，路由可能把里面的一句记成你说的，再常驻进画像 | 路由写入时拿这条会话里你最近亲手写的三句话核对：正文大半出自这几句才算你说的，否则记成路由的推断，界面上是「对话里记下」。模型和工人记下、你没确认的，不进工人画像：工人能改文件、能往外发东西。在记忆页改一下就算确认 |
| 问「上周做了什么」找不到 | 只按词找，问句里没有和记忆相同的词 | 问句说到过去哪几天（昨天、上周三、上周、这个月、最近、写明的日期）时，那几天记下的、或正文写着那几天的记忆排在最前，召回也带上。只在问的时候这样，「今天帮我写周报」不算；将来的日子不算 |
| 召回带回几条差不多的 | 不看已经挑了什么 | 几乎一样的几条只带第一条 |
| 「下个月」「周末」存下来就是一句空话 | 换算不成日子的说法没人提醒 | 回执里点出来，让路由照人说的写具体哪天 |

挖掘：主会话路由本来就会记下人说出的长期事实，这一轮让它写入时看到库里相近的旧记忆，改口就换掉。普通会话的 `memory_write` 走同一条写入，回执里同样列出相近的旧记忆；那边每次写入本来就要人批准。邮件和日历仍然只进主动性信号，不进记忆。

整理不交给模型反复改写。[Zhang 等人（2026-05）](https://arxiv.org/abs/2605.12978) 发现每做完一题就让模型改一次记忆，十轮后正确率从 100% 掉到 52.6%；只留原始经历不改写的对照组反而不差。所以这里自动合并的只有只差格式的，改口交给写的人决定，工单经历原样留着。

记忆页每条写出出处、到哪天为止或已经过去、最近改过的时间、改过几次（悬停看以前的说法）和说过几次。

还没做：

1. **用到的记忆看得见。** 回复下面列出这一轮带进去的记忆，可以说「不对」「别再提」。要先在会话事件里记下带了哪几条。
2. **写入回执能撤销。** 主会话里记下或改口时出一张能撤销的小卡。
3. **整理借简报那一次模型，只提建议。** 简报本来就要叫一次模型，可以顺手请它判断哪些相近的记忆是同一件事、哪些是改口。它只提建议，由人在信里点「对」或「不对」，不直接改记忆；攒够十几条新经历再做一次。
4. **记忆的上限和后排。** 现在不设上限。条目多了以后，很久没用到的退到后排：还能搜到，但不进画像，当事人亲口说的不退。
