## 主张

仓库级 context 文件（`AGENTS.md` / `CLAUDE.md`）被工具厂商大力推荐，但没有严谨证据说它能提高真实任务成功率。作者在 SWE-bench Lite（LLM 生成的 context 文件）和自建 CTXbench（仓库里已经有开发者写的文件）上，对照「无文件 / LLM 生成 / 人写」。

跨多个 agent 与模型：context 文件 **一般不提高** 成功率，平均推理成本 **+20% 以上**。指令会被遵守，所以成本涨在多探索、多测试、多推理。仓库概览（厂商常推荐的那种）不帮助导航。人写文件略好于 LLM 生成，统计上也不稳。结论：context 文件适合写 **非标准惯例**（用哪套工具），不要写百科全书；上线前必须评测。

## 对 Yoyo 的含义

`LoadWorkspaceRules` 已经读 `YOYO.md` / `AGENTS.md` / `CLAUDE.md` 并有 token 上限。Galster 说这些文件是公约；这篇说公约很容易变成税。evolve 若往 playbook / instruction 里堆仓库导览，会同时踩 ACE 膨胀和这篇的成本税。

质量门（HarnessEvolve / FRONTIER 议程 3）应禁止「仓库概览」类 bullet，只留非标准惯例。

## 可偷 / 应拒

- 偷：人写、最短、只写非默认惯例；用 Harbor 测「加这段针有没有涨分」。
- 拒：用 LLM init 自动生成长 `AGENTS.md` 当默认产品路径。
- 已对齐：workspace 针有上限；不要为此删掉公约文件 — 办公场景的「用哪套 office 工具」正是非标准惯例。
