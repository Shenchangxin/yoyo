## 主张

Agent 靠改上下文而不是改权重。先前方法有 brevity bias（为了短而丢掉领域洞察）和 context collapse（反复重写把细节磨掉）。ACE 把上下文当成会生长的 playbook：Generator → Reflector → Curator，结构化增量更新。离线改 system prompt、在线改 agent memory。AppWorld 上用较小开源模型打到生产级 agent 的平均水平，并在更难 split 上超过。

## 对 Yoyo 的含义

`Curate` 与 `StageACE` 是这篇的直接实现。在线路径 **只写 staging**，避免「对话里点一次赞就改了你信任的 harness」。Compact 文案明确禁止提及 playbook — 防止把受信任钉子摘要掉，这是 ACE 反 collapse 在 runtime 上的对应物。

2026 年的 Self-Harness / ModularRSI 把「可进化对象」从 playbook 扩到整个 harness。ACE 仍然约束 **playbook 这一层必须增量**。不要用 Self-Harness 当借口去整页重写 bullets。

## 可偷 / 应拒

- 已偷：delta、helpful/harmful、在线/离线两条路径。
- 拒：把 curator 做成整份 prompt 重写器。
- 谱系提醒：首发 2025。前沿判断以 2026 的 Self-Harness 门与 ModularRSI 模块化为准。
