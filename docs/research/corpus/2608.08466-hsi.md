## 主张

冻结模型 `M`，在三层范围上改自己：

1. 任务 harness `H` — 执行任务。
2. Evolver — 改 `H`。
3. Meta-evolver — 改 evolver 的策略代码。

Meta-evolver 自己的执行逻辑来自 `godel_evolution_init/`，**永不修改**，作为外锚，避免无限制自指。`using_harness(agent, task)` 注入签名保持不变。Thinking on/off：任务执行关推理以钉死模型天花板，改写时打开推理。

BALROG 上中等难度环境有大幅进度增益；超出骨干能力的 NLE 上 harness 进化无效。两个界：反馈保真度、骨干能力。

## 对 Yoyo 的含义

Yoyo 的 L4（Go、eval、vault、updater）就是这篇说的外锚，而且比「冻结 meta-evolver 文件」更硬：evolver 策略代码也不让 agent 改。这是产品决策，不是功能缺失。

可对齐的部分：固定 injection seam（我们的 tool schema / Harbor agent 入口）、按任务族热替换 harness（我们已有模型指纹 refs，还没有任务族 refs）。

不要做的部分：让 evolve 去改 `internal/evolve`。那会把威胁模型里「候选插件替换评测器」变成默认路径。

## 可偷 / 应拒

- 偷：外锚；固定 seam；用 thinking-off 隔离「是 harness 在涨还是测试时多想了」。
- 拒：第三层自改 Go。
- 看：任务族 harness 热替换（个人 OS 的「写周报」vs「改代码」可能不该共用 playbook）。
