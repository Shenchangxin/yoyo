## 主张

官方摘要只取一句：开放世界任务在 harness 设计时未见过，也没有 ground-truth verifier，任务特异的 RSI 又带不走。Harness² 用两层递归回答这件事（权重始终冻结）。

1. **任务层 Propose–Probe–Compose。** 先跑当前 harness 的 reference 执行（揭示行为，不判对错），再分维提出 INV（怎么干活）与 DOM（从业者知识）编辑，在同一任务上探测，从行为对照合成 successor。没有分数、没有 rubric。预算 `k` 可以走并行（更宽）或串行（更深），两边 rollout / improver 会话数对齐。
2. **Harnessing 层经验库。** 任务结束后不把本题 harness 整棵传给下一题。Reflector 按组件写 `helped / hurt / no observed effect / confounded`，只有同时具备 `cue / lesson / evidence` 的 lesson 才入库；否则 `NO_ENTRY`。库按领域隔离，带的是整棵 adopted 树，不是摘要。

可编辑表面是八个文件组件：system prompt、guardrails、memory、tool guidance、skills、scripts、subagents、plugins。改进阶段的 `RunView` **永不携带分数**；judge 在 selection 提交之后才跑，方法代码不 import 它。

报告：WorkBuddy-Bench 最高 +11.5、JobBench +4.5、LAB partial pass +11.8；加大 `k` 还有增益。仓库 `PINNED.md` 写明历史跑次可能用了不同任务与部署，数字不能当 Yoyo 的承诺。

## 对 Yoyo 的含义

Yoyo 已经会 **对着 Harbor 套件进化全局 harness**（Self-Harness）。缺的是 **对着当前用户任务、没有标签时当场改脚手架**。这不是替换 `ShouldPromote`，而是 Propose 轨上的可选深进化：结果 pin 到当前 thread（`HarnessPolicy=pin`），过 Harbor 才考虑 canary，checkout 才动 `refs/active`。

和已有文献的分工：

- **Self-Harness**：套件级、有 verifier。已经是 `yoyo evolve`。
- **RHI**：任务特化、少步数、成对修订。轻；没有对照探测，也没有跨任务经验库。
- **ModularRSI**：模块归因 + 进化集 ⊥ 评测集。管全局晋升怎么不被套件背题。
- **Harness²**：无 GT 的同任务对照 + 按领域蒸馏。管开放世界里「这一题」和「下一题怎么 refine」。

挂载点已经在：`internal/session` 的 `follow_active | pin`，`internal/evolve` 的 `Cycle`，Harness 工作区的 Propose 轨。v1 合同见 [architecture/ppc-overlay.md](../../architecture/ppc-overlay.md)。不要把 Python 实验栈（OpenCode / Codex runner、Linux `fcntl`、第三方基准）嵌进 Wails 桌面。

## 可偷 / 应拒

- 偷：Propose–Probe–Compose；INV / DOM 分维；领域经验库与 `NO_ENTRY`；匹配预算恒等式 `R=4k, P=3k`；产物匿名选择（harness 藏起来，选 base 合法）；证据以文件提供；grader 泄漏 tripwire；always-on 是最贵选项。
- 拒：嵌入 Python / 第二套 runtime；PPC 或经验库自动移动 `refs/active`；执行器不限网、关沙箱（论文自己记录 Codex 曾下到过 JobBench rubric）；meta-evolver 改 `internal/evolve`；把本题事实写入全局 playbook（DOM 模板自己也禁止）。
- 已落地：会话 overlay width/depth（`R=4k,P=3k`）、INV/DOM、匿名选择（finals-only，选未改 final 即 KEEP_BASE）、KEEP_BASE、按领域经验库（CAS hash + cue/lesson/evidence 或 NO_ENTRY）、Propose 账本与 BoN 同屏。仍拒：嵌入 Python / 自动移动 active / L4 evolver。
