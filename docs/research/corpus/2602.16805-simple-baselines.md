## 主张

很多「用 LLM 进化代码」的管线看起来很强，却没跟简单基线比。作者用 **IID 随机采样** 和 **顺序条件采样（SCS）**，在数学界、agentic scaffold 设计、机器学习竞赛三个域上，用同样的 API / 评测次数 / 墙钟，打平或超过更复杂的进化方法。

设计 scaffold 时：高方差 + 小数据集 → 选中过拟合的脚手架，手写 majority-vote 反而最好。作者主张更稳的评测（降随机、仍负担得起），并认为搜索空间和 prompt 里的领域知识往往比进化算法本身更决定上限。

## 对 Yoyo 的含义

这是 Wang et al.（匹配预算）的会场亲戚：复杂 evolve 可能只是多搜了几次。FRONTIER 议程 1（evolve 和 `eval --best N` 画同一张预算图）同时被两篇论文要求。不要用「我们有 archive / ACE curator」当成已经赢过随机采样的证据。

## 可偷 / 应拒

- 偷：evolve 实验室加 IID / SCS 对照；重复评测降方差；搜索空间（L1 表面）比更花哨的 proposer 更值钱。
- 拒：为了「更像进化算法」去改 Go 或加 meta-evolver。
