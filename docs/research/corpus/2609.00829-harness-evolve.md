## 主张

自进化 harness 有三个经典坑：

1. **Credit assignment** — 终局对错说不清是哪一步害的。
2. **Shortcut learning** — 背题而不是长能力。
3. **Catastrophic forgetting** — 新补丁打掉旧能力。

HarnessEvolve 把执行智能体与进化管线拆开（执行 / 评价 / 优化 / 门控各是独立模块）。关键技巧：在 **给定标准答案** 时生成参考轨迹，拿失败执行去对齐，抽取误差再聚类。候选必须过两道门：

- **质量门** — 过滤数据泄漏与 prompt 膨胀。
- **性能门** — 当前 batch 变好且不伤最近的 batch；epoch 末在 held-out 上选快照。

## 对 Yoyo 的含义

我们的 mine 已经在做失败聚类，但没有「如果模型看见了答案会怎么走」这条参考轨迹。Harbor 任务带人写的参考解，这是现成的信号，evolve 目前没用。

质量门是立刻能做的：playbook 总 token 上限（AssemblePins 已有预算，但 evolve 接受补丁时不强制）；禁止把 held-in `instruction.md` 粘进 bullet。

执行与进化解耦：Yoyo 已经是「同一模型两种角色」（loop vs proposer），还没有独立的 gating agent。Keep it simple：门继续用 `ShouldPromote`，质量规则用确定性检查，不必再请一个模型当门卫。

## 可偷 / 应拒

- 偷：参考轨迹对齐；质量门；batch 级遗忘检查。
- 拒：把标准答案泄漏给 **执行** 智能体（只给进化管线）。
- 注意：不是所有 Yoyo 任务都有唯一参考解（办公文档）。参考轨迹先用在 `evals/` 的 coding/terminal 任务上。
