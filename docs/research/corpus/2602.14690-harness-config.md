## 主张

Harness engineering 把焦点从「模型上下文」扩到仓库里那些 Markdown/JSON 旋钮。作者整理八种机制（Context Files、Skills、Subagents、Commands、Rules、Settings、Hooks、MCP），扫 2853 个 GitHub 仓库：

- Context Files 占绝对多数，常常是唯一机制。`AGENTS.md` 成为跨工具公约。
- Skills / Subagents 很少被真正用；技能多半是静态说明书，不是可执行脚本。
- Claude Code 用户覆盖的机制最广。

## 对 Yoyo 的含义

`LoadWorkspaceRules` 读 `YOYO.md` / `AGENTS.md` / `CLAUDE.md` 并加预算，正是这篇建议的起点。Skills 进 CAS 而不是「再丢一个 markdown 到仓库里碰运气」，是我们比平均 GitHub 仓更进一步的地方。

实证也警告：用户不会主动写 skills。产品要让 evolve / skill market **替用户产生**技能，同时保持未签名不能上 active。

## 可偷 / 应拒

- 偷：AGENTS.md 作为跨工具针；别指望用户配置八种机制。
- 拒：把八种机制做成八个设置页。Harness 实验室是 Propose → Prove → Promote，不是配置博物馆。
