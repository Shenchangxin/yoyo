## 主张

长程 skill 若把观察、动作、中间推理全部 append 进对话，会延迟爆炸并毒化上下文。SKILL.state 每步只给模型三样东西：不可变的 skill 规格、当前结构化执行状态、最新观察。中间推理在写出合法状态更新后立刻丢掉。跨数据集与环境：准确率升，累计 token 降。显式执行状态是与架构无关的长程抽象。

## 对 Yoyo 的含义

`Shape` 已经对 **工具正文** 做了 stub+spill，但 skill 执行仍是主对话里的散文。周报 / 会议纪要这类打包 skill 跑得足够长时，会撞上这篇描述的失败。正确的下一形状：skill 运行时有一份可变 state（存在 spill 或 session 目录），主 loop 只看到 state 摘要。

这是 runtime 变更，风险高于 evolve 的证据格式变更。所以议程把它放在 1–4 之后。

## 可偷 / 应拒

- 偷：状态与规格分离；丢掉中间思维；每步只喂最新观察。
- 拒：把 playbook 也变成可变 state 随便改 — playbook 仍走 ACE delta + Harbor。
- 与 Shape 的关系：Shape 管对话投影；SKILL.state 管 skill 内部。两者可以共存。
