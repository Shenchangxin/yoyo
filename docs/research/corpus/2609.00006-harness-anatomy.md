## 主张

Agent = 模型 + harness。Harness engineering 在 2026 年初被命名为一门学科。本文不打榜，只解剖十一套生产代码（Claude Code、Codex CLI、Gemini CLI、Mistral Vibe、OpenHands、Aider、Mini-SWE-Agent、Hermes、Pi、OpenCode、OpenClaw）外加 Databricks Omnigent 这个 meta-harness。

七个子系统：loop、tools、context、safety、orchestration、extension、（以及他们画出的最小/最大实现）。约四百万行里两条缺席经得起扩大语料：

- **没有** 生产 runtime import LangChain / LangGraph / AutoGen（Gemini CLI 也不用 Google 自己的框架）。
- **没有** 用向量嵌入检索代码。场上跑的是手写 async loop 与 ripgrep / tree-sitter / glob / 自动发现的 Markdown。

SKILL.md 采用率 9/11，超过 MCP 的 8/11。ACP 在六个系统里出现，并长出第三角色：harness hosting（OpenHands 跑别人的 Claude/Codex/Gemini）。一个季度的纵向 diff：Codex 原样抄 Claude 的 hook 词汇。命题：2026 上半年 coding harness 从工具变成平台。

文末 18 条设计建议和约 90 行最小可行 harness。

## 对 Yoyo 的含义

PRODUCT.md「禁止前端第二套 loop、禁止 LangChain」与这篇观察同构。Yoyo 已经是「可托管的 core + JSON-RPC」，方向是平台而不是 IDE 克隆。

对照七子系统：loop（`runtime`）、tools（workspace + MCP + WASM）、context（`Shape`）、safety（capability + safeguard + isolation）、orchestration（depth-1 task）、extension（skills + MCP）。缺的是他们记录的大规模 hook 生态和会话导入器（Codex 在读 Claude 的 settings）。不要为了兼容去实现 27 个 hook 事件；要保持 Yoyo 的 hook 集合小而可审计。

## 可偷 / 应拒

- 偷：七子系统清单当架构 checklist；最小可行 harness 对照我们的 seed snapshot；平台化（多 client 一个 core）。
- 拒：向量记忆；为「看起来完整」去抄全套 Claude hooks。
- 已对齐：无通用框架；grep/glob；skills + MCP；签名信任分层。
