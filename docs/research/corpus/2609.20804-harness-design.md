## 主张

固定执行 loop，只改三块：planning、action space、context management。四模型 × SWE-Verified × TB 2.1，176 个匹配设置。

关键结果：

1. 窗口越紧，上下文管理越值钱，主要靠 **防止 overflow**。
2. **先规则裁剪、再 LLM 摘要** 效率最好；让被裁内容可恢复，模型几乎不用，准确率不涨。
3. Planning 对弱模型是准确率脚手架，对强模型主要省成本。
4. 预定义工具帮 bash 弱的模型；bash 强的模型用纯 shell 更便宜。

## 对 Yoyo 的含义

`context_shape.go` 的顺序已经是「最便宜且无损的先做」：spill/preview → microcompact → snip，LLM 摘要只在 checkpoint 且不碰 playbook。与 (2) 同构。

spill + `recall_context` 是「可恢复」。这篇说可恢复性不涨分。我们保留 spill 是为了 **审计和对证**（PRODUCT：truth in the audit trail），不是幻想模型会主动召回。不要为此删 spill。

Plan mode 对强模型「省钱」符合 composer 里的 Plan chip：提案、不写盘。
