## 主张

LLM agent 的表现由 **模型 × harness** 共同决定。有效 harness 是模型特异的，人工为每个新模型重做一遍不可扩展。Self-Harness 让 **同一个固定模型** 改进自己的 operating harness，不依赖人类工程师，也不依赖更强的外部 Meta-Harness。

闭环三步：

1. **Weakness Mining** — 在可验证任务上跑当前 harness，按失败轨迹聚类，得到模型特异的失败机制，而不是一条条孤立错误。
2. **Harness Proposal** — 针对这些机制提出 **多样且最小** 的 harness 修改，不推翻控制结构。
3. **Proposal Validation** — 回归测试；held-in 与 held-out 都要过；通过的编辑才合并进下一版。

在 TB2.0、SWE-bench Verified、AppWorld 上，三个家族的模型（MiniMax M2.5、Qwen3.5-35B-A3B、GLM-5）九个组合的终态 harness **held-in 与 held-out 都升**，相对增益最高约 132%。定性结果：留下的不是空话，而是「早点写产物文件」「别死磕同一条失败命令」这类可执行机制。

## 对 Yoyo 的含义

这就是 `yoyo evolve`。对应：

- `internal/evolve/mine.go` 的 Signature 聚类
- `internal/evolve/propose.go` 的 K 提案与「不要改 loop / evaluator / secrets」
- `internal/eval/promote.go` 的非回归门
- `refs/models/<fp>/active` 的模型特异指针

产品层我们加了一道门：论文把通过回归的编辑并进 `h_{t+1}`；Yoyo 并进的是 `refs/canary`，`refs/active` 仍要人。这是桌面工作站该有的恐惧，不是对论文的不忠。

## 可偷 / 应拒

- 偷：失败机制必须聚类；提案必须最小；held-out 痕迹不得进入挖掘。
- 已偷：三步循环、非回归、模型指纹。
- 拒：用更强模型当外部优化器（论文对比的 Meta-Harness 范式）。
- 下一刀：论文后期版本把机制扩到 SWE / AppWorld 的「产物处理 / 补丁验证 / 应用状态」——我们的 mine 分类器还偏终端失败，可以按基准族扩 signature。
