## 主张

Agent 基准碎片化：环境复杂、接入各异。本文做三件事：

1. **Adapters** — 把 80+ 基准接到任意 agent，靠 code review 与 parity 实验证明「Harbor 上的分 ≈ 原基准的分」。
2. **大规模评估** — 8 个模型 × 54 个基准，每个模型既跑 Terminus-2 也跑一种原生 harness。
3. **Harbor-Index** — 从 6627 候选里筛出 82 道又难又多样的题（29 个基准）。没有任何被评的模型–harness 组合超过 30%；最强（GPT-5.5 + Codex）28.0%。负担得起，信号高。

Verifier 与 agent 分 sandbox：grader 只拿声明的产物，agent 看不到测试，堵住一整类 reward hacking。

## 对 Yoyo 的含义

我们实现的是 Harbor **任务布局** 与本地 verifier，不是 Harbor 产品本身。Index 作为 **transfer 门** 比继续堆 `evals/` 更值：难、短、跨域。

独立 verifier sandbox 与威胁模型「eval gaming」对齐。当前若 `environment/Dockerfile` 存在，verifier 在镜像里跑且 `--network=none`；Index 的形态是 grader 连产物都只收声明文件。那是下一轮隔离加硬。

## 可偷 / 应拒

- 偷：parity 思维（adapter 必须证明测的是同一件事）；Index 作迁移检查；verifier 看不到 agent 文件系统。
- 拒：把 54 个基准全搬进桌面 CI。
- 产品：`yoyo eval --transfer` 已存在但未挂 Index。挂的时候仍然 **不得** 把题目 id 送给 proposer。
