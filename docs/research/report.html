固定模型，进化 harness。

下一跃迁是模块化、评测不相交、预算诚实。不是更宽的搜索。evolve 改不了 Go、评测器和密钥。

脚手架确实涨分。Self-Harness 在九个模型–基准组合上，终态 harness 的 held-in 与 held-out 都升。这是 evolve 的主定理。

但涨分很容易是过拟合，或只是多搜了几次。把钱对齐以后，自动进化并不稳定地赢过当场多试几次。解法不是把 K 开得更大，而是进化数据与评测基准不相交，并且一次只动一块。

生产系统已经平台化。解剖过的十一套代码里，没有人用 LangChain，也没有向量检索。Yoyo 站在这条线上：一个 Go 内核，多个 client。不要倒回去做 IDE 皮肤。

已经站稳的几件事。新 harness 先在 canary 里活，你自己 checkout 才算数。内核和评测器，智能体碰不到。上下文是规则裁出来的，不是模型摘要。期末考卷对出题的人保密。

评测要诚实

进化集和晋升集切开。同一轮 evolve 花掉的钱，拿去跑 best-of-N 和随机对照。Harbor 报告核对它自己写下的预测。声称完成之前，先跑一层便宜的行为检查。

进化要能归因

proposer 看失败簇，和同一道题做对的那次对比，而不是单条轨迹。一次只动一个运行时模块，过门再 merge。playbook 设长度上限，禁止抄题，禁止仓库导览。

技能先不动

可执行 skill 和执行状态外置都还早。那是改 runtime，不是改证据格式。

先看清楚，再改结构。

完成前面两段之后，再考虑外部进化集。技能状态不要先上。

这周

实验室已经把 evolve、best-of-N、IID/SCS 画在同一张花费表上。proposer 看失败簇和同任务对比。canary 有确定性质量门。Harbor 核对 predicted_fixes，hit 为零不得晋升。四个秒级行为探针进实验室，不进默认晋升。

这季

密封套件已切成 evolve-set 与 promote-set。一个提案一个 surface，不相交才 merge。Harbor-Index 只以三道 stand-in 作 transfer，id 永不进 Propose。82 题不进桌面 CI。

先别动

技能执行状态外置。能改的是 playbook 和 skills；工具要签名；loop 形状要人点头；Go、评测器、密钥没人改。

明确不做的。

读这些是为了拒绝时有词。不是待办。

不要改内核

不要进化智能体源码，也不要进化进化程序本身。不要用更强的外部模型当教练。不要在桌面里训一个 harness 工程师。不要为 RSI 引入世界模型。

不要在考题上刷分

不要在评测集上进化，再报同一套分数。不要复杂进化却不跟随机采样、best-of-N 比预算。不要靠模型说自己没作弊。

不要把产品做回皮肤

不要前端第二套 loop。不要向量检索代码。不要让模型写长说明书和仓库概览。不要无界 harness 递归。不要整页重写 system prompt。不要让 proposer 去翻评测器和密钥。
