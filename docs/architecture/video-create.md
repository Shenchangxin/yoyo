# 视频 · 创作：导演 Agent

创作是成片台（finish desk），也是视频的前台。它不是 Yingce `/create`，也不是第二个 agent loop。
这一页写清创作桌怎么从“人选按钮”变成“人说想法、Agent 定方案、人确认一次”。

## 1. 原则

1. **一个 Agent。** 创作桌就是导演会话（`conductorLane`）。意图、简报、确认、执行都在这条 Go 循环上，前端只画它的工具结果。
2. **说话即意图。** 模态和片型不再让人先选。导演按一句话和桌上的素材判断该剪、配音、翻拍、出片、出图，还是去工坊。
3. **花钱前只问一次。** 会花额度的方案先出一张简报：做什么、用到哪些账号、缺哪个。操作者点头才开工。这张卡不因为空闲自动通过。
4. **只说真的。** 简报里的账号只来自 `provider_menu`（已启用且有钥匙）。缺的写成缺，不编造。
5. **首屏只留 Agent 和灵感。** 机器人、一句话、带模型芯片的输入框、三句例子，下面是案例目录（点一张只填进输入框）。没有片型菜单和工坊入口；要选文件的两件事（添加素材、翻拍参考片）在输入框的 `+` 里。

## 2. 流程

```
说 / 拖素材 → 导演判断意图 → video_brief（结构化简报，对照账号）
  → 不花额度：直接做（剪辑、看片、路由）
  → 花额度：确认卡（hold，不空闲通过）→ 开拍 / 改一下 / 先不做
  → 执行（update_plan 是唯一进度来源）→ 送到成片台
```

## 3. `video_brief` 契约

导演工具，只在 `conductorLane` 挂上。参数：

| 字段 | 取值 | 说明 |
|---|---|---|
| `intent` | `cut` `dub` `remake` `film` `still` `short` `drama` `canvas` | 必填。对不上返回错误，不猜 |
| `format` | `talking` `drama` `podcast` `interview` `ranking` `explainer` `narration` | `intent=film` 时用，空时按 `explainer` |
| `subject` | 文本 | 主题，操作者原话里的 |
| `seconds` | 5–180 | 空或越界时按意图给默认值 |
| `aspect` | `9:16` `16:9` `1:1` | 空时 `9:16` |
| `voice` `style` `source_hash` | 文本 | 可空；`source_hash` 只能是已入库的哈希 |

结果（JSON）：`brief`（归一后的参数）、`needs`（会用到的能力）、`have`（每种能力可用的账号名）、`missing`、`spend`、`local`（本机可兜底的能力，例如语音走 edge-tts）。

`spend` 为真时，宿主在同一次调用里抛出确认卡（`ask_user`，`hold: true`），结果末尾带 `confirmed: go|edit|stop`。
导演看到 `go` 才调用花额度的工具；`edit` 按操作者的话改简报再来一次；`stop` 收尾。

## 4. 确认卡 `hold`

`AskForm.hold` 为真时：

- 桌面不倒计时，`askCanIdle` 为假。
- 没有操作者（无界面）时，答复是“未确认，不要花额度”，不是“按默认继续”。

前后端的 `askCanIdle` 同时认 `hold`。

## 5. 创作桌

| 之前 | 之后 |
|---|---|
| 选择视频 · 翻拍 · 剪视频 · 生图 · 生视频（1+7 片型）· 配音，六个按钮把 `@skill:` 写进输入框 | 三句例子（没片子时是想法，有片子时是怎么剪），点一下只填进输入框。片型、出图、配音、去工坊都由导演从一句话里判断 |
| 模式、绑定、成片、翻拍稿多个布尔量在 App 与 HomeStage 里各算一遍 | 纯函数 `createDeskView` 给出一个视图名：`launch` `cut` `film` `remake` |
| 绑定后的“剪这条 / 配音”按钮 | 换成三句例子。添加素材、翻拍参考片进输入框 `+` 菜单。案例目录留在空桌的输入框下方 |
| 创作桌不显示模型芯片 | 显示。还没有会话时选的模型记成默认 |

## 6. 不做什么

- 不在前端加创作状态机、不加第二套审批 UI、不留 legacy 路由。
- 不改 Yingce `/create`。
- 不让导演在 `video_brief` 之外自行判断“这一步不花钱”。

## 7. 指标与评测

指标：首个产物用时、到首个产物的点击数、简报一次通过率、花额度前确认率（应为 100%）。

评测（`evals/`）：

- `create-brief-before-spend`：生成类请求先出简报，不直接调花额度的工具。
- `create-brief-no-invent`：没有账号时简报写缺，不编造账号或哈希。
- `create-route-cut`：“剪这条”走剪辑，不出简报、不花额度。

## 8. 翻拍能力清单

这份清单原来写成代码（`internal/video/film/contract.go` 的 `film.Contract`），只有一个测试在读，现在作为文档放在这里。每一行要么已实现，要么明确不做；新增能力时在这里加一行。

| 编号 | 能力 | 状态 | 说明 |
|---|---|---|---|
| workflow | 参考片或描述变成可再跑的工程 | 已实现 | `FromReference` 与 `FromTemplate` 会保存词、镜头和待办 |
| words | 词轴，改一行只重排这一行 | 已实现 | 词级时间来自标注 JSON 或按字均分；本机有 whisper.cpp 时用它的句子再切开 |
| variant | 换宿主、产品、语言、画幅、开头时只重做变的步骤 | 已实现 | 开头只改第一行。价格和收口只改最后的画面。变体另存，原片不动。换语言时用对话连接逐行重写并重排时间 |
| structure | 排行榜、播客分屏、街采揭示、评论贴纸、区域字幕、卡点 | 已实现 | 排行榜每一行有一张图的位置，图从图像连接来。播客两边都在，中间交出产品。街采逐条揭示。贴纸和字幕跟当前词走。切点落在词上 |
| code | 代码画面，没有生成账号也能出图 | 已实现 | 进程内按词画出画面；本机有 Chrome 或 Edge 时另存一张浏览器截图。有垫乐时混在人声下面 |
| models | 图、视频、语音、抠像走已启用的连接 | 已实现 | 拒绝名称或地址里带 hypihub 的连接。抠像预设火山引擎主体分割、remove.bg、Photoroom，并按各自的公开接口发请求。配乐走 MiniMax、Mureka、ElevenLabs、Stability。Lyria 和 Suno 仍是预设，没有统一请求体时该步等待 |
| plan | 计划、花费、构建、失败证据 | 已实现 | 构建留下任务；失败的一步不抹掉其余产物 |
| tools | 媒体、词级标注、下载、区域、浏览器 | 已实现 | ffmpeg 沿用现有安装。yt-dlp 可从官方发布下载到本机 bin。没有区域程序时用 ffmpeg cropdetect。词级标注调用 whisperx 的 json 输出。浏览器从 PATH 或 YOYO_BROWSER 读取 |
| identity | 其他产品的名称、命令和清单格式 | 不做 | 翻译树不进安装包 |
| gateway | 托管模型网关客户端 | 不做 | 生成只走 Yoyo 连接 |
| tenancy | 多租户托管这套引擎 | 不做 | 每个用户在自己的机器上跑 |
| foreign-ui | 另一套工作室的界面源码 | 不做 | 预览、任务和产物在创作台 |
| runtime | npm 与 Node 模块运行时 | 不做 | 工程是 Go 结构 |
| vault | 第二套密钥库 | 不做 | 账号留在连接库 |
| samples | 上游例子里的具体片子 | 不做 | 结构要有，题目用 Yoyo 自己的 |
